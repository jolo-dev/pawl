# pawl — AI Agent Instructions

## Project Overview

pawl (Proficient AWS Library) is a TypeScript monorepo providing opinionated AWS CDK constructs, Lambda handler wrappers, and an AI-powered infrastructure CLI. It targets Node.js 22+ and uses Bun as the package manager and test runner.

## Stack

- Runtime: Bun (package manager, bundler, test runner)
- Language: TypeScript 5.x (strict mode, no `any`)
- Linting/Formatting: Biome (tabs, double quotes, recommended rules)
- Validation: Zod (runtime schema validation)
- CDK: aws-cdk-lib 2.x with cdk-nag for compliance
- Lambda: AWS Lambda Powertools (Logger, Tracer, Metrics)
- Testing: Bun test with Localstack (via Docker/Testcontainers)
- CI: GitHub Actions
- Docs: Astro Starlight with TypeDoc

## Commands

- Install: `bun install`
- Build all: `bun run build`
- Test all: `bun test`
- Lint/format check: `bun lint`
- Lint/format fix: `bun lint:fix`
- CDK synth (example): `cd example/some-service && npx cdk synth`
- Docs dev: `cd docs && bun run dev`

## Conventions

### General

- Use `export` (named exports), never `export default`
- Use Zod for all runtime validation and schema definitions
- No `any` — use `unknown` with type narrowing or Zod parsing
- Prefer `const` over `let`; never use `var`
- Error handling: throw typed errors, never swallow exceptions silently

### CDK Constructs (`packages/cdk/`)

- Every construct MUST extend `BasicConstruct` from `./src/basic-construct.ts`
- Props interfaces use Zod schemas for validation
- Constructs should be self-contained: include IAM permissions, alarms, and tags
- Use `cdk-nag` to validate compliance in tests
- Export all public constructs from `index.ts`

### Lambda Handlers (`packages/lambda/`)

- Use the `handlerFactory` pattern (see `./src/base/handler-factory.ts`)
- Every handler wraps AWS Lambda Powertools (Logger, Tracer, Metrics)
- Handler functions must be `export`-ed (required for Lambda runtime)
- First parameter is always `serviceName` (used for CloudWatch identification)
- Export all handlers from `index.ts`

### Tests

- Test files: `*.test.ts` in a `tests/` directory per package
- CDK tests: use snapshot testing and cdk-nag assertions
- Lambda tests: use fixture JSON events from `tests/*.json`
- Integration tests use Localstack via Docker (requires Docker running)

## Boundaries

- Do NOT modify `cdk.out/` — it's generated output
- Do NOT modify `docs/src/content/docs/cdk/` or `docs/src/content/docs/lambda/` — auto-generated by TypeDoc
- Do NOT add dependencies without explicit approval — we audit packages
- Do NOT use `aws-cdk-lib` directly in consumer code — use `@pawl/cdk` abstractions
- Do NOT use raw AWS Lambda types — use `@pawl/lambda` handler wrappers
- Keep `packages/` independent: `@pawl/lambda` has no CDK dependency

## Verification

Before completing any change:

1. `bun lint` — must pass with zero errors
2. `bun test` — all tests must pass
3. If you added a CDK construct, add a test in `packages/cdk/tests/`
4. If you added a Lambda handler, add a test in `packages/lambda/tests/`
5. If you changed public API, ensure `index.ts` exports are updated
