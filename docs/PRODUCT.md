# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

TypeScript developers building AWS infrastructure and Lambda services.

## Product Purpose

pawl provides opinionated AWS CDK constructs, Lambda handler wrappers, and infrastructure tooling that help developers ship reliable services with less repeated setup. Success means developers can use safer, validated primitives while retaining clear technical understanding of the infrastructure they deploy.

## Positioning

pawl packages AWS best practices into reusable primitives with built-in validation, observability, IAM permissions, alarms, and compliance support rather than leaving each service team to assemble those concerns independently.

## Operating Context

Developers use the documentation while designing infrastructure, implementing services, learning pawl's abstractions, and consulting generated API references. The documentation covers the CDK and Lambda libraries alongside tutorials, local-development guidance, and reference material.

## Capabilities and Constraints

- Preserve technical accuracy and all existing documentation content.
- Preserve generated TypeDoc content and make generated-page improvements through shared configuration or styling.
- Keep CDK, Lambda, and CLI concepts distinct and navigable.
- Support desktop, tablet, and mobile documentation workflows.

## Brand Commitments

The product name is pawl (Proficient AWS Library). Existing product terminology, logos, and factual claims must remain intact.

## Evidence on Hand

- Existing documentation content under `src/content/docs/`.
- Generated CDK and Lambda API references.
- Existing pawl logo and Excalidraw diagrams used throughout the documentation.
- Repository implementation, tests, and examples are the authority for technical claims.

## Product Principles

- Make AWS best practices the default rather than optional assembly work.
- Keep complex infrastructure concepts understandable.
- Prefer validated, observable, compliant primitives.
- Preserve technical precision while reducing cognitive overhead.

## Accessibility & Inclusion

The web documentation must remain keyboard accessible, responsive, readable, and compatible with established web accessibility expectations.
