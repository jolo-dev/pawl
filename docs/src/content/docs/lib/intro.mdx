*pawl* (**P**roficient **AW**S **L**ibrary) (pronounce: pɔːl) is a one-stop shop that contains best practices for using AWS CDK, AWS Lambda, and any AWS-related library.
The goal is that it is the only dependency that provides coding primitives to deploy your service successfully. In addition, these libraries are compliant and contain best practices when dealing with AWS.
Furthermore, it should simplify the infrastructure decision so that the developer can focus on logic implementation.

## Features

This repository offers:

- Standards and Best practices
- Powerful AWS CDK Constructs
- Typesafe Code Building Blocks
- Battery-included Library for your Lambda

![Goal](../../../assets/goal.excalidraw.svg)

## Why do we need such a library?

The following problems will be addressed.

### Avoid different versions

When working across multiple repositories, version drift becomes a problem. Different repos may use different versions of `aws-cdk-lib` or Node.js runtimes.

![Problem 1 - Different versions](../../../assets/problem-1.excalidraw.svg)

AWS CDK wants you to install it globally, which may lead to different versions on your machine.

### Different implementation

Another problem is the different ways to implement AWS Resources. For example, in one repository the older API Gateway is used whereas another repo uses the newer version, or different Node.js versions are used.

![Problem 2 - Different Implementation for same thing](../../../assets/problem-2.excalidraw.svg)

### Non-compliant AWS Resources

From a compliance perspective, AWS resources may need to fulfill requirements such as being in the right VPC or having encryption enabled. The constructs make it easy to choose the right configuration and abstract these concerns away.

![Problem 3 - Non-Compliance](../../../assets/problem-3.excalidraw.svg)
