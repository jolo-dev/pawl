**Goal:** Create a 1,500–2,200 word Markdown blog post explaining what pawl is, why it exists, and the infrastructure problem it solves.

**Architecture:** Use a problem → solution → real example narrative. Start with the repeated operational burden of AWS projects, introduce pawl's principles and package boundaries, then ground the explanation in the CodeCommit auto-reviewer and durable Lambda workflow. The final artifact lives in the user's Obsidian Vault, not in the repository.

**Tech Stack:** Markdown, Mermaid, TypeScript examples, repository sources from `@pawl/cdk`, `@pawl/lambda`, and `@pawl/cli`.
