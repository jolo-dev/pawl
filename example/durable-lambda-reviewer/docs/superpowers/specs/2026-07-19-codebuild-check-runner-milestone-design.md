# CodeBuild Check Runner Milestone Design

**Date:** 2026-07-19
**Status:** Draft — pending user approval
**Milestone:** Fifth of the durable reviewer feature implementation (master plan Task 12)

## 1. Purpose

Replace the `NoopCheckRunner` stub with a real `CodeBuildCheckRunner` that runs repository-configured checks (`repositoryConfig.checks`) at the exact immutable source commit via AWS CodeBuild, polls for completion, and returns bounded/scrubbed logs. This completes the reviewer's review pipeline — checks + model + reconciliation all real.

The router/reviewer/Bedrock/reconciler milestones are merged. The `CheckRunner` port currently returns an empty result; the review engine passes the (empty) checks to the model as context. This milestone makes the checks real so the model sees pass/fail status + bounded logs per check.

## 2. Confirmed decisions

- **Synchronous `run` with internal polling.** The existing `CheckRunner.run(input): Promise<CheckRunResult>` interface stays synchronous from the caller's view. The adapter starts the build, polls `BatchGetBuilds` until terminal (with a bounded poll loop + timeout), then reads logs and returns. This keeps the port unchanged and avoids a workflow refactor to a start/poll/resume model. The polling happens inside the workflow's durable `context.step("run-review")`, so a step timeout surfaces as a `timed-out` result; the durable SDK handles replay.
- **One CodeBuild build per `run` call, not per check.** The buildspec runs all configured checks sequentially in one build; each check's exit code is captured via per-check log markers the buildspec emits. This minimizes build starts (cost/latency) and matches how the `checks` array is a list of shell commands. The build spec is generated by the adapter from `repositoryConfig.checks` + `install.command`.
- **`sourceVersion` = exact source commit.** `StartBuildCommand.sourceVersion` is set to `snapshot.sourceRevision` (the immutable commit). Never the branch. The master plan's "exact destination commit reads" is honored: the build checks out the source commit.
- **No secrets in the build.** Environment variables are derived only from validated base config — no PR content, no IAM role passthrough, no `iam:PassRole`. The build uses the CodeBuild project's fixed service role (Pawl's `CodeBuildProject` owns it). The reviewer's `StartBuild` call passes only `environmentVariablesOverride` for check names/timestamps (non-secret), never credentials.
- **Log bounding + scrubbing.** `boundedLog` is capped at a configurable max (default 4 KB per check). Logs are scrubbed of AWS-internal tokens and the reviewer's own Powertools secrets via a denylist regex. `logTruncated` is true when the cap is hit.
- **Status mapping:** CodeBuild `SUCCEEDED` → `passed`; `FAILED` → `failed` (check exit code from build); `STOPPED`/`FAULT`/`TIMED_OUT` → `infrastructure-failure` (retryable true for `FAULT`, false for `STOPPED`); a poll-loop timeout → `timed-out`. Service failures (`TooManyRequestsException`, 5xx) are NOT turned into check findings — they surface as `infrastructure-failure` with `retryable: true` (master plan Step 4).
- **IAM:** add a Pawl `CodeBuildProject` to the stack; `codeBuildProject.grantRunAndRead(reviewer)`. Pawl's helper owns the `AwsSolutions-IAM5` suppression for the build-ARN wildcard + log-stream wildcard. The construct test asserts `codebuild:StartBuild` + `BatchGetBuilds` + logs read on the reviewer role.
- **No live-AWS tests.** Fake `CodeBuildTransport` (injectable `StartBuild`/`BatchGetBuilds`/CloudWatch logs). No real CodeBuild calls.

## 4. Architecture

### 4.1 CodeBuildCheckRunner

```ts
export interface CodeBuildTransport {
  startBuild(input: StartBuildCommandInput): Promise<StartBuildCommandOutput>;
  batchGetBuilds(input: BatchGetBuildsCommandInput): Promise<BatchGetBuildsCommandOutput>;
  getLogEvents(input: GetLogEventsCommandInput): Promise<GetLogEventsCommandOutput>;
}
```

`run(input)`:

1. Generate a buildspec from `input.checks` + `input.installCommand`: each check runs as `echo "<<<CHECK:$name:START>>>"` … run command … `echo "<<<CHECK:$name:EXIT:$?>>>"`. Install runs first if present.
2. `startBuild({ projectName, sourceVersion: input.snapshot.sourceRevision, buildspecOverride: JSON.stringify(buildspec), environmentVariablesOverride: [{ name: "PAWL_CHECK_RUN_ID", value: <uuid> }] })`. Record `build.id`.
3. Poll `batchGetBuilds({ ids: [build.id] })` every `pollIntervalMs` (default 5s) until `build.buildStatus` is terminal or `maxPollMs` (default `repositoryConfig.checks[].timeoutSeconds` sum, capped at 15 min) elapses.
4. On terminal: read CloudWatch logs via `getLogEvents` for the build's log group/stream, bounded to `maxLogBytes` (default 4096) per check, scrubbed.
5. Parse per-check exit markers from the log; map to `CheckResult`.
6. Map overall: `SUCCEEDED` → all `passed`; `FAILED` → per-check `failed`/`passed`; `STOPPED`/`FAULT` → `infrastructure-failure`; poll timeout → `timed-out`.

### 4.2 Buildspec generation

```yaml
version: 0.2
phases:
  install: # only if installCommand present
    commands:
      - <installCommand>
  build:
    commands:
      - echo "<<<CHECK:name:START>>>"
      - <command> || echo "<<<CHECK:name:EXIT:$?>>>"
      - echo "<<<CHECK:name:EXIT:0>>>" # if command succeeded
      # ... per check
```

Exit-code capture uses `|| echo` so a failing check records its code and the build continues (so all checks report, not just the first failure). The overall build status is `FAILED` if any check exited non-zero (the buildspec exits non-zero at the end if any marker shows failure).

### 4.3 Log scrubbing + bounding

- Cap each check's `boundedLog` at `maxLogBytes`; set `logTruncated: true` if the raw slice exceeds.
- Scrub: redact AWS request IDs, IAM token patterns (`AKIA[0-9A-Z]{16}`), and Powertools secret substrings via regex. The scrubbed log is what the model sees.

## 7. IAM (delta)

`CodeBuildProject` is instantiated with a restricted config (private subnets, deny-by-default egress, no package-registry override this milestone — Pawl defaults). `codeBuildProject.grantRunAndRead(reviewer)` grants:

- `codebuild:StartBuild` on the project ARN.
- `codebuild:BatchGetBuilds` on `arn:codebuild:...:build/<projectName>:*`.
- `logs:DescribeLogStreams`/`GetLogEvents`/`FilterLogEvents` on the project's log group.

All `AwsSolutions-IAM5` suppressions for the build-ARN + log-stream wildcards are owned by Pawl's `suppressReviewerWildcards` helper. No stack-side suppression. The construct test asserts the actions are present and cdk-nag is clean.

## 8. Testing strategy

### 8.1 CodeBuildCheckRunner unit test

Fake `CodeBuildTransport`:

- `startBuild` returns `{ build: { id: "build-1", buildStatus: "IN_PROGRESS" } }`.
- `batchGetBuilds` returns a configurable sequence of statuses (IN_PROGRESS → SUCCEEDED/FAILED/STOPPED/FAULT).
- `getLogEvents` returns canned log events with the `<<<CHECK:...>>>` markers.

Cases:

1. **StartBuild source version**: `startBuild` called with `sourceVersion === snapshot.sourceRevision`; `buildspecOverride` contains each check's command.
2. **Passed**: poll → SUCCEEDED; logs show all checks `EXIT:0` → all `passed`.
3. **Failed**: poll → FAILED; logs show one check `EXIT:1` → that check `failed`, others `passed`.
4. **Infrastructure-failure (FAULT)**: poll → FAULT → `infrastructure-failure` with `retryable: true`.
5. **Infrastructure-failure (STOPPED)**: poll → STOPPED → `infrastructure-failure` with `retryable: false`.
6. **Timed-out**: poll never reaches terminal within `maxPollMs` → `timed-out`.
7. **Log bounding**: log events exceed `maxLogBytes` → `boundedLog` truncated, `logTruncated: true`.
8. **Log scrubbing**: log events contain `AKIAEXAMPLE1234567890` → redacted in `boundedLog`.
9. **No secrets in StartBuild**: `environmentVariablesOverride` contains no credentials (only `PAWL_CHECK_RUN_ID`).

### 8.2 Construct test (extended)

- One `AWS::CodeBuild::Project` resource exists.
- Reviewer role has `codebuild:StartBuild` + `BatchGetBuilds` + the three logs actions.
- cdk-nag clean (Pawl-owned suppressions).

## 9. Acceptance criteria

1. `src/adapters/codebuild-check-runner.ts` implements `CheckRunner` using `StartBuild`/`BatchGetBuilds`/CloudWatch logs with an injectable transport.
2. `StartBuild.sourceVersion` is the exact source commit; buildspec is generated from validated checks; no secrets passed.
3. Status mapping: SUCCEEDED→passed, FAILED→per-check failed/passed, STOPPED/FAULT→infrastructure-failure, poll timeout→timed-out.
4. Logs are bounded (`maxLogBytes`) with `logTruncated` flag and scrubbed of AWS/IAM tokens.
5. The stack instantiates `CodeBuildProject` and grants the reviewer `StartBuild`/`BatchGetBuilds`/logs via `grantRunAndRead`; cdk-nag clean.
6. The workflow passes `repositoryConfig.checks` + `install.command` to the check runner; the handler's env path constructs `CodeBuildCheckRunner`.
7. `cdk synth` clean; existing 220 tests remain green; new adapter + construct tests added on top.
8. No Pawl library changes and no live AWS calls.

## 10. Decisions (approved by user — use judgment on all 4)

1. **Poll defaults.** `pollIntervalMs: 5000`, `maxPollMs: 900_000` (15 min). Matches typical check durations; bounded so the durable step surfaces a `timed-out` result rather than hanging.
2. **`maxLogBytes` per check.** 4096 (4 KB). Keeps the model prompt bounded; the `logTruncated` flag signals when the cap was hit.
3. **CodeBuild image.** `aws/codebuild/standard:8.0` (Ubuntu 22.04, Node 22). Matches the Lambda runtime family.
4. **Repository config loading.** The adapter is fully implemented this milestone; the workflow still passes `DEFAULT_REPOSITORY_CONFIG` (empty checks) at runtime until `.pawl/reviewer.json` loading lands in a follow-up. This keeps the milestone focused on the CodeBuild mechanics; config loading is a small, separable wiring task.
